# Лекция 5. Entity Framework Core (EF Core). ORM для C#

**Цель лекции:** сформировать представление об ORM как способе работы с базой
данных через объекты C#; научиться настраивать `DbContext` для PostgreSQL,
выполнять CRUD-операции, строить LINQ-запросы и управлять схемой базы данных
с помощью миграций EF Core 10.

**Предварительная подготовка:** классы C#, LINQ, `async`/`await`, основы SQL.

## План лекции

1. Ручной доступ к данным и ORM: какую рутину берёт на себя отображение.
2. Устройство EF Core: сущность, `DbContext`, `DbSet` и провайдер.
3. CRUD-операции и отслеживание изменений.

## 1. Что такое ORM

Реляционная база данных хранит данные в таблицах, а программа на C# работает
с объектами. При ручном доступе через ADO.NET для каждой операции приходится
составлять SQL-строку, читать результат и преобразовывать его в объекты. Такой
код разрастается и ломается при изменении схемы.

**ORM (Object-Relational Mapping, объектно-реляционное отображение)** —
технология, которая сопоставляет классы языка программирования таблицам базы
данных и берёт на себя преобразование между объектами и строками таблиц.

| Объект в C# | Элемент базы данных |
| --- | --- |
| класс `Student` | таблица `Students` |
| свойство `Id` | столбец `Id` |
| объект `Student` | одна строка таблицы |

ORM не отменяет SQL: запросы выполняет сервер СУБД, а отображение убирает
рутинное преобразование.

## 2. Entity Framework Core

**Entity Framework Core (EF Core)** — современная ORM от Microsoft для
платформы .NET. EF Core 10 — LTS-версия (Long Term Support, долгосрочная
поддержка), выпущенная в ноябре 2025 года и поддерживаемая до 10 ноября
2028 года; для сборки и запуска нужен .NET 10.

СУБД подключаются через провайдеры — NuGet-пакеты:

| СУБД | Пакет провайдера |
| --- | --- |
| PostgreSQL | `Npgsql.EntityFrameworkCore.PostgreSQL` |
| SQL Server | `Microsoft.EntityFrameworkCore.SqlServer` |
| SQLite | `Microsoft.EntityFrameworkCore.Sqlite` |

Для PostgreSQL используется провайдер Npgsql:

```bash
dotnet add package Npgsql.EntityFrameworkCore.PostgreSQL --version 10.0.3
```

Возможности EF Core:

- описание модели классами C# и её отображение на таблицы;
- CRUD-операции (Create, Read, Update, Delete) через объекты;
- LINQ-запросы, которые провайдер переводит в SQL;
- асинхронные операции (`async`/`await`) и миграции.

### 3.1. Сущность (entity)

**Сущность** — класс C#, который соответствует таблице в базе данных. Свойства
класса становятся столбцами, а экземпляры — строками.

```csharp
public class Student
{
    public int Id { get; set; }

    // required требует задать значение при создании (C# 11+)
    public required string Name { get; set; }

    public int Age { get; set; }
}
```

`Id` EF Core по соглашению считает первичным ключом. Ключевое слово
`required` обязывает задать имя при создании объекта.

### 3.2. Контекст базы данных (DbContext)

**`DbContext`** — основной класс для работы с EF Core. Он представляет сессию
с базой данных: хранит настройки подключения, модель и отслеживаемые сущности.
Один экземпляр контекста рассчитан на одну короткую операцию (unit of work):
создать, выполнить работу, сохранить изменения, освободить ресурсы.

```csharp
using Microsoft.EntityFrameworkCore;

public class SchoolContext : DbContext
{
    public DbSet<Student> Students => Set<Student>();

    protected override void OnConfiguring(
        DbContextOptionsBuilder optionsBuilder)
    {
        string connectionString =
            Environment.GetEnvironmentVariable("MDK0104_DB")
            ?? throw new InvalidOperationException(
                "Не задана переменная MDK0104_DB");

        optionsBuilder.UseNpgsql(connectionString);
    }
}
```

`OnConfiguring` настраивает провайдер при создании контекста. Строка
подключения берётся из переменной окружения `MDK0104_DB`, поэтому пароль не
попадает в репозиторий; значение в кабинете выдаёт преподаватель. В ASP.NET
Core контекст регистрируют через `AddDbContext`.

### 3.3. Набор сущностей (DbSet)

**`DbSet<T>`** представляет коллекцию объектов, соответствующих таблице:
через него выполняются запросы, добавление и удаление. Свойство `Students`
объявлено как `Set<Student>()`: EF Core создаёт набор при обращении, а
компилятор не предупреждает о неинициализированном свойстве.

### 3.4. Отслеживание изменений (ChangeTracker)

При загрузке сущности контекст запоминает её состояние. `ChangeTracker`
фиксирует изменения, а `SaveChanges` генерирует `UPDATE` только для изменённых
столбцов. Поэтому в примере обновления не нужен `Update`. Для чтения без
правок применяют `AsNoTracking()`.

## 4. Основные операции

Примеры выполняются в `Program.cs` с top-level statements, поэтому `await`
доступен без `Main`. Подразумевается `using Microsoft.EntityFrameworkCore;`.
Фрагменты предполагают созданный контекст:
`await using var context = new SchoolContext();`; запросы асинхронны.

### 4.1. Добавление записи

```csharp
Student student = new() { Name = "Alice", Age = 20 };
context.Students.Add(student);
await context.SaveChangesAsync();
```

`Add` ставит объект в очередь, `INSERT` выполняет `SaveChangesAsync`.

### 4.2. Чтение данных

```csharp
List<Student> students = await context.Students
    .AsNoTracking()
    .OrderBy(s => s.Id)
    .ToListAsync();

foreach (Student s in students)
{
    Console.WriteLine($"{s.Id}: {s.Name}, {s.Age}");
}
```

Если в таблице уже есть Alice и Bob, вывод будет таким:

```text
1: Alice, 20
2: Bob, 22
```

### 4.3. Обновление данных

```csharp
Student? student = await context.Students.FirstOrDefaultAsync();
if (student is not null)
{
    student.Age = 21;
    await context.SaveChangesAsync();
}
```

Запрос без `AsNoTracking` возвращает отслеживаемый объект: изменение `Age`
попадает в `ChangeTracker`, и `SaveChangesAsync` сохраняет его.

### 4.4. Удаление записи

```csharp
Student? student = await context.Students.FirstOrDefaultAsync();
if (student is not null)
{
    context.Students.Remove(student);
    await context.SaveChangesAsync();
}
```

`Remove` помечает сущность на удаление, а `DELETE` выполняется при
`SaveChangesAsync`.

## 5. LINQ-запросы с EF Core

Запрос строится стандартными операторами LINQ: `Where` фильтрует, `OrderBy`
сортирует, `Select` проецирует данные. Выражение имеет тип `IQueryable<T>` и
выполняется отложенно: SQL отправляется в базу только при вызове терминального
оператора, например `ToListAsync`.

```csharp
await using var context = new SchoolContext();

List<Student> adults = await context.Students
    .AsNoTracking()
    .Where(s => s.Age >= 18)
    .OrderBy(s => s.Name)
    .ToListAsync();
```

SQL можно посмотреть методом `ToQueryString`; он предназначен для отладки, а
не для выполнения вручную. `Where`, `OrderBy` и `Select` только строят запрос;
асинхронные версии есть у операторов, выполняющих его: `ToListAsync`,
`FirstOrDefaultAsync`, `AnyAsync`, `CountAsync`. Не каждый метод C# переводится
в SQL: неподдерживаемое выражение приводит к исключению во время выполнения.

## 6. Миграции

Схема базы данных меняется вместе с моделью. **Миграция** — C#-класс с
методами `Up` (применить изменение) и `Down` (откатить его), который EF Core
генерирует по разнице между моделью и снимком предыдущей версии.

Миграции выполняются через **.NET CLI** в терминале VS Code. Инструмент
`dotnet ef` ставится один раз, пакет `Microsoft.EntityFrameworkCore.Design` —
в проект:

```bash
dotnet tool install --global dotnet-ef --version 10.0.15
dotnet add package Microsoft.EntityFrameworkCore.Design --version 10.0.15
```

Версии зафиксированы на ноябрь 2026 года: `dotnet-ef` и пакеты EF Core — 10.x,
провайдер Npgsql — совместимый с EF Core 10. Команды выполняются в папке
проекта; перед ними задайте `MDK0104_DB` в терминале:

```bash
dotnet ef migrations add InitialCreate
dotnet ef database update
```

- `dotnet ef migrations add InitialCreate` создаёт миграцию и снимок модели в
  папке `Migrations`; файлы добавляют в систему контроля версий;
- `dotnet ef database update` применяет миграции и пишет историю в служебную
  таблицу `__EFMigrationsHistory`.

Созданные миграции применяют и при запуске через `Database.MigrateAsync()`,
как в примере ниже. `EnsureCreated()` не ведёт историю миграций, поэтому вместе
с ними его не используют.

## 7. Преимущества EF Core

- Ускоряет разработку: меньше ручного кода для чтения и записи.
- Типизированные LINQ-запросы: многие ошибки видны при компиляции.
- Один код можно подключить к разным СУБД через провайдеры.

## 8. Ограничения EF Core

- Сложные запросы могут работать медленнее ручного SQL.
- Труднее контролировать сгенерированный SQL; помогают логи и `ToQueryString`.
- Возможна проблема N+1: один запрос за списком и отдельный запрос за
  связанными данными для каждой строки.

## 9. Пример полного кода

**Файл Student.cs:** класс `Student` приведён в разделе 3.1.

**Файл SchoolContext.cs:** код контекста приведён в разделе 3.2.

**Файл Program.cs (top-level statements):**

```csharp
using Microsoft.EntityFrameworkCore;

await using var context = new SchoolContext();

// Применяем миграции при запуске.
await context.Database.MigrateAsync();

// Добавление
context.Students.Add(new Student { Name = "Alice", Age = 20 });
context.Students.Add(new Student { Name = "Bob", Age = 22 });
await context.SaveChangesAsync();

// Чтение
List<Student> students = await context.Students
    .AsNoTracking()
    .OrderBy(s => s.Id)
    .ToListAsync();
foreach (Student s in students)
{
    Console.WriteLine($"{s.Id}: {s.Name}, {s.Age}");
}

// Обновление: Update() не нужен
Student? firstStudent = await context.Students.FirstOrDefaultAsync();
if (firstStudent is not null)
{
    firstStudent.Age = 21;
    await context.SaveChangesAsync();
}

// Удаление
Student? lastStudent = await context.Students
    .OrderByDescending(s => s.Id)
    .FirstOrDefaultAsync();
if (lastStudent is not null)
{
    context.Students.Remove(lastStudent);
    await context.SaveChangesAsync();
}
```

Вывод при первом запуске на чистой базе:

```text
1: Alice, 20
2: Bob, 22
```

## 10. EF Core и безопасность

- **Параметризация.** EF Core, как правило, передаёт значения из LINQ как
  параметры SQL, а не вставляет в текст, что защищает от инъекций.
- **Сырой SQL.** `FromSqlRaw` принимает готовую строку: конкатенация с вводом
  создаёт инъекцию. Используйте параметры или `FromSql` с интерполяцией.
- **Права и секреты.** Приложение подключается ролью с минимальными правами;
  строка подключения берётся из переменной окружения.
- **Логи.** `EnableSensitiveDataLogging()` пишет значения параметров в журнал;
  включайте только при отладке.
- **Валидация.** ORM не заменяет проверку входных данных и ограничения базы.

## Резюме

- ORM сопоставляет классы C# таблицам; EF Core — ORM от Microsoft для .NET 10.
- `DbContext` — короткоживущая сессия с базой, `DbSet` — набор сущностей
  таблицы, `ChangeTracker` помнит изменения до `SaveChanges`.
- CRUD выполняется через `Add`, LINQ-запросы и `Remove`; чтение без правок
  ускоряет `AsNoTracking()`.
- Миграции хранят историю схемы в коде и применяются через `dotnet ef` или
  `MigrateAsync`.
- EF Core не отменяет SQL: нужны параметризация, минимальные права роли и
  защита строки подключения.
