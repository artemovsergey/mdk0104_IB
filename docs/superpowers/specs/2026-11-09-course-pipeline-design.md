# Спецификация: конвейер учебных материалов МДК 01.04 (ИБ)

Дата: 09.11.2026
Статус: утверждена рабочая версия (решения по умолчанию, см. §15)
Репозиторий: https://github.com/artemovsergey/mdk0104_IB
Ветка: `feature/course-pipeline`

## 1. Контекст

`mdk0104_IB` — курс «МДК 01.04 Системное программирование» для специальности ИБ,
2026/27. 18 markdown-файлов, 4 раздела + экзамен, средний объём файла ~10 тыс. знаков.

Что уже есть:

- Контент написан и в целом плотный: определения, аналогии, таблицы, примеры на C#.
- `tools/generate_lecture_pptx.py` (668 строк, python-pptx) — готовый генератор
  презентаций 16:9 с фирменной палитрой и блоком «ЧТО ЗАКОНСПЕКТИРОВАТЬ».
  Сгенерированы 5 колод (лекции 1–5).
- README со структурой курса и орг-блоком.

Что мешает:

1. **Разметка неоднородна.** В лекциях 1–2 заголовки `### **1. …**` + `#### **…**`,
   в лекции 3 — `### 1. …` без жирного, в лекции 5 — `## **1. …**`.
   Генератор PPTX понимает только один из вариантов, поэтому колоды расходятся
   с текущими исходниками и воспроизводятся не гарантированно.
2. **Нет выхода в документы.** DOCX/PDF для печати и методического кабинета
   собираются вручную или не собираются вовсе.
3. **Нет проверок.** Опечатки, битые ссылки, устаревшие версии .NET, расхождение
   README и файлов ловятся только глазами.
4. **Схем нет.** Архитектура .NET, три столпа ООП, состояния потоков, EF Core
   pipeline просятся в диаграммы, но в markdown их нет.
5. **Скриншоты потеряны.** 13 ссылок вида `images/screenshot*.png` в практиках
   ведут на несуществующие файлы; в истории git их тоже не было.

Целевой стек курса: .NET 10, C# 14, VS Code + C# Dev Kit, PostgreSQL,
без Docker и без Visual Studio.

## 2. Цель и границы

**Цель:** один воспроизводимый конвейер, который из markdown-исходников курса
собирает комплект материалов для студентов и преподавателя и не пропускает
структурный брак.

**В границах:**

- нормализация разметки без изменения смысла текста;
- DOCX (редактируемый, для методички и правок);
- PDF (печать и раздача, вёрстка Typst);
- PPTX (презентации к лекциям, развитие существующего генератора);
- сборник на раздел и на весь курс (опция `--book`);
- схемы из `mermaid`-блоков;
- QA-отчёт с кодами ошибок и понятными сообщениями;
- GitHub Actions, собирающий артефакты на каждый push;
- пилот на Разделе 1, затем раскатка на все 4 раздела, СР и экзамен.

**Не в границах:**

- переписывание содержания лекций и практик;
- сайт курса (Quarto) и LMS-интеграция — отдельные задачи;
- автопроверка студенческих работ;
- генерация изображений нейросетью;
- восстановление утраченных скриншотов;
- личные данные преподавателя и групп в публичном репозитории.

**Анти-цели:**

- конвейер не должен требовать правки исходников, чтобы что-то собрать;
- сборка не должна зависеть от Windows, Visual Studio, Docker или LibreOffice;
- артефакты не коммитятся в репозиторий (только в CI-артефакты и релизы).

## 3. Ключевые решения

| # | Решение | Обоснование |
|---|---------|-------------|
| 1 | Нормализация в `build/normalized/`, исходники не трогаем | Нулевой риск для контента; канон можно принять в исходники позже |
| 2 | Единый канонический markdown как вход для всех рендереров | Один парсер, одно поведение, предсказуемые слайды и документы |
| 3 | DOCX — pandoc + `reference.docx` | Штатный путь, стили правятся в Word без кода |
| 4 | PDF — pandoc → Typst → PDF | Кириллица, код, таблицы, точная геометрия; без LaTeX на 2 ГБ |
| 5 | PPTX — существующий python-pptx генератор, вынесенный в модуль | Уже есть фирменный стиль и приём с конспектом |
| 6 | Схемы — Mermaid CLI в SVG | Текстовый источник, диффы в git, чёткий вектор в PDF |
| 7 | QA — обязательный шаг, падает только на структурном браке | Конвейер не должен блокироваться из-за отсутствующего контента |
| 8 | Запуск локально и в GitHub Actions одной командой | «Собрать как в CI» должно быть тривиально |
| 9 | Отсутствующие разделы и картинки — WARN, а не ERROR | Иначе пилот не собрать: в корпусе есть неполные практики и потерянные скриншоты |
| 10 | DOCX называет шрифт Times New Roman, PDF использует Liberation Serif | Word у методкабинета отрисует родной шрифт; локально Liberation метрически совместим |

## 4. Архитектура

```
course/**/*.md
      │
      ▼
[normalize]  ──►  build/normalized/**.md      (канон, идемпотентно)
      │
      ├──► [figures]  mermaid ─► build/figures/*.svg
      │
      ├──► [docx]     pandoc + reference.docx ─► dist/docx/*.docx
      ├──► [pdf]      pandoc ─► typst ─► typst ─► dist/pdf/*.pdf
      └──► [pptx]     python-pptx ─► dist/pptx/*.pptx
      │
      ▼
[qa]  ──►  dist/qa-report.md  +  код возврата
      │
      ▼
[manifest] ─► dist/manifest.json (файл, размер, страниц/слайдов, sha256)
```

Команды: `normalize`, `figures`, `docx`, `pdf`, `pptx`, `book`, `qa`, `build`, `clean`.
`build` = normalize → figures → docx → pdf → pptx → qa → manifest.

## 5. Канонический формат и профили

Канон — это **профиль с синонимами**, а не жёсткая схема. Нормализатор приводит
заголовки к каноническим именам по таблице синонимов, но не добавляет разделы,
которых в файле нет. Отсутствие обязательного раздела — это WARN и запись
в «долговой список» QA.

### 5.1. Профиль «Лекция»

```markdown
# Лекция N. Название

**Цель лекции:** одно-два предложения.
**Аудитория:** ИБ-243, 2 курс.

## План лекции
1. Пункт
   - подпункт

## 1. Раздел
### 1.1. Подраздел
Текст, списки, таблицы, код, схемы.

## Резюме
## Контрольные вопросы
## Материалы
```

Обязательные: `План лекции`, `Резюме`, `Контрольные вопросы`.
Рекомендуемые: `Цель лекции`, `Аудитория`, `Материалы`.

### 5.2. Профиль «Практика» / «Самостоятельная работа»

```markdown
# Практическая работа N. Название

## Цель работы
## Теоретическая часть
## Ход работы
## Практический пример
## Варианты заданий
## Критерии оценки
## Контрольные вопросы
## Требования к репозиторию
```

Обязательные: `Цель работы`, `Ход работы`, `Варианты заданий`, `Критерии оценки`.
Рекомендуемые: `Теоретическая часть`, `Практический пример`, `Контрольные вопросы`,
`Требования к репозиторию`.

### 5.3. Профиль «Экзамен»

`examen.md` — титул, условия, список вариантов, критерии. Обязательные:
`Варианты заданий`, `Критерии оценки`. Оформляется как практика, но без
«Хода работы».

### 5.4. Таблица синонимов

| Канон | Синонимы в корпусе |
|-------|--------------------|
| Цель работы | Цель, Цель лекции, Цель работы:, Тема и цель |
| Теоретическая часть | Краткая справочная информация, Теоретические сведения |
| Ход работы | Порядок выполнения, Задание |
| Практический пример | Пример практического задания, Практический пример, Пример реализации, Пример выполнения |
| Варианты заданий | 15 вариантов простых заданий, 15 вариантов заданий, Варианты |
| Критерии оценки | Критерии оценивания |
| Контрольные вопросы | Вопросы для самопроверки |
| Требования к репозиторию | Структура репозитория, Структура репозитория для Gogs, Структура репозитория для студента |
| Резюме | Резюме лекции, Итоги |
| План лекции | План лекции:, План |

### 5.5. Правила нормализации

- ровно один `#` вне блоков кода; уровни не прыгают через один;
- `### **План лекции:**` → `## План лекции` (и так для остальных канонов);
- нумерованные разделы любого исходного уровня и без жирного → `## N. Название`;
- подразделы → `###`;
- разделители `---` удаляются (в DOCX/PPTX они дают пустые блоки);
- маркеры списков → `-`, вложенность 4 пробела;
- у блоков кода пустой язык сохраняется, чтобы QA отличал пропуск;
  рендереры трактуют его как `text`, QA выдаёт WARN;
- у изображений непустой alt и путь относительно файла;
- заголовки внутри четырёхбэктиковых блоков (примеры `readme.md`) не трогаются.

Нормализация идемпотентна: повторный прогон не меняет файл. Она не переписывает
формулировки, не сокращает и не дополняет текст.

## 6. Рендереры

### 6.1. DOCX

- pandoc 3.1.x, `--reference-doc=tools/coursekit/templates/reference.docx`,
  `--toc --toc-depth=2`.
- Титульный лист — `templates/titlepage.md`, подставляется из `course.yml`;
  в публичной версии ФИО преподавателя — плейсхолдер.
- Стили в `reference.docx`: Times New Roman 14 pt (в DOCX указано имя
  `Times New Roman`, чтобы Word в методкабинете не подменял шрифт), интервал 1,5,
  поля 3/1,5/2/2 см, абзацный отступ 1,25 см, выключка по ширине, колонтитул
  с номером страницы, стиль `Source Code` (Consolas 10 pt, без отступа).
- Таблицы — стиль `Table` с видимыми границами, шапка полужирная.
- Формулы — родные OMML (pandoc), не картинки.
- Отсутствующая картинка заменяется рамкой с подписью «Скриншот: <alt>»
  и не ломает сборку.

### 6.2. PDF

- pandoc `-t typst` → `build/typst/*.typ` → `typst compile`.
- Шаблон `templates/gost.typ` (имя историческое, оформление — методичка):
  A4, поля 3/1,5/2/2 см, Liberation Serif 14 pt, межстрочный 1,5, нумерация
  страниц, колонтитул с названием дисциплины, оглавление, сноски, таблицы
  с повторяющейся шапкой, подсветка кода.
- Проверяем: кириллица, разрывы таблиц, длинные строки кода, висячие заголовки.

### 6.3. PPTX

База — `tools/generate_lecture_pptx.py`: палитра, `header_band`, `code_box`,
`conspect_box`, 13,333×7,5. Выносим в `coursekit/render_pptx.py` и расширяем:

- титульный слайд: дисциплина, номер и название лекции, специальность, год;
- слайд «План лекции» из блока плана;
- разделители разделов;
- содержательные слайды: 1 тезис = 1 слайд, ≤ 6 пунктов, ≤ 70 слов;
- код: ≤ 14 строк на слайд, перенос по логическим блокам;
- таблицы: ≤ 5 столбцов, иначе разбивка;
- изображения и схемы: вписывание по пропорциям, подпись;
- блок «Что законспектировать» на каждом содержательном слайде;
- заметки докладчика: полный текст соответствующего раздела;
- в конце — резюме и контрольные вопросы.

**Паритет** с текущими колодами определяется не числом слайдов, а покрытием:
все пункты плана, все разделы лекции, ни одного обрезанного блока, есть заметки.
Текущие `.pptx` в `course/**/Презентация N/` остаются до приёмки новых колод;
удаляются отдельным коммитом после подтверждения.

### 6.4. Схемы

Блок ```` ```mermaid ```` в markdown → SVG в `build/figures/`, имя —
`<файл>-<номер>.svg`. Рендер: `@mermaid-js/mermaid-cli` (Chrome уже есть).
В PDF вставляется SVG, в DOCX/PPTX — PNG 2x для совместимости.

Пилотные схемы (добавляются в содержание отдельным коммитом, на ревью):

- Лекция 1 — архитектура .NET: C# → IL → CLR → ОС, рядом CTS/CLS/FCL;
- Лекция 3 — три столпа ООП и связь класс/интерфейс/наследование;
- Лекция 4 — состояния потока и путь `async/await`;
- Лекция 5 — конвейер EF Core: модель → LINQ → SQL → PostgreSQL.

### 6.5. Сборник

`--book` склеивает нормализованные файлы раздела (или всего курса) в один поток:
титул, оглавление, сквозная нумерация, разрыв страницы перед каждым документом.
Сборник не заменяет отдельные файлы, а дополняет их.

## 7. QA

`coursekit qa` пишет `dist/qa-report.md` и возвращает код 1 при ERROR.

| Уровень | Примеры |
|---------|---------|
| ERROR | нет `#`; два `#` вне кода; незакрытый блок кода; битая локальная ссылка на существующий раздел; файл из README не существует; ошибка чтения/кодировки |
| WARN | нет обязательного раздела; раздел короче 300 знаков; лекция короче 8 или длиннее 35 тыс. знаков; > 40 слайдов; > 70 слов на слайде; отсутствующая картинка; блок кода без языка; двойные пробелы; прямые кавычки в русском тексте; `TODO`/`FIXME`; устаревшие `net8.0`, `Visual Studio`, `ChromeDriver` |
| INFO | оценка времени чтения; число слайдов; число схем; список сокращений; «долговой список» недостающих разделов |

Дополнительно для кода: баланс скобок в C#-блоках, отсутствие табов,
длина строки ≤ 100 символов. Полная компиляция примеров — отдельная задача,
в пилот не входит.

Допустимые языки блоков: `csharp`, `bash`, `json`, `sql`, `xml`, `yaml`,
`markdown`, `text`, `console`, `csproj`, `diff`, `html`, `css`, `js`, `ts`.
Неизвестный язык — WARN, подсветка как `text`.

## 10. CI

`.github/workflows/materials.yml`:

- триггеры: push в `course/**`, `tools/**`, `course.yml`; pull_request; ручной запуск;
- job `build`: Ubuntu, Python 3.12, pandoc 3.1, Typst, Node 20 + mermaid-cli;
- шаги: normalize → figures → docx/pdf/pptx → qa → upload-artifact;
- кэш: pip, npm, шрифты;
- артефакт: `dist/` с именами `<курс>-<раздел>-<файл>.<ext>`;
- QA-ошибки валят job, WARN — только в отчёт.

## 12. Верификация

1. `normalize --check` на чистом дереве — ноль изменений (идемпотентность).
2. `qa` — ноль ERROR на пилотном разделе; отчёт приложен.
3. PDF: `pdfinfo` (страницы, размер A4), `pdftoppm` первых страниц → просмотр.
4. DOCX: `python-docx` читает файл; стили и поля совпадают с шаблоном;
   дополнительно `libreoffice --headless --convert-to pdf` как независимая проверка.
5. PPTX: `python-pptx` читает файл; число слайдов; ни один текстовый блок
   не выходит за границы слайда; выборочный рендер в PNG для глазной проверки.
6. CI: workflow зелёный, артефакт скачивается и открывается.
7. Содержание: выборочная сверка 10 фрагментов исходник ↔ PDF ↔ PPTX.

## 13. Риски

| Риск | Митигация |
|------|-----------|
| Нормализация испортит авторскую разметку | Работаем в `build/`, исходники не трогаем; diff канона проверяется на пилоте |
| Typst-шаблон не потянет сложные таблицы | Ограничение 5 столбцов; перенос шапки; проверка на практике 1 |
| PPTX генератор не переносит длинные пункты | Автоматическая разбивка + проверка границ |
| Нет шрифтов Times New Roman | DOCX называет TNR, PDF использует Liberation Serif |
| Mermaid в headless Chrome падает в CI | `--no-sandbox`, пин версии, кэш |
| Конвейер усложняется быстрее, чем приносит пользу | Каждый этап даёт артефакт; QA полезен уже без рендеров |
| Потерянные скриншоты попадут в печать как пустые рамки | Плейсхолдер заметный, WARN в отчёте, список файлов на пересъёмку |
