## ORM заменяет ручное преобразование строк объектами

- ORM — отображение классов C# на таблицы базы
- ADO.NET: SQL-строка, чтение, сборка объекта вручную
- Такой код разрастается и ломается при изменении схемы
- `Student` — таблица `Students`, свойство — столбец, объект — строка
- SQL остаётся: ORM убирает только преобразование

## DbContext — сессия с базой на одну короткую операцию

- Порядок работы: создать, выполнить работу, сохранить, освободить
- Строка подключения — из MDK0104_DB, пароль не в репозитории

```csharp
public class SchoolContext : DbContext
{
    public DbSet<Student> Students => Set<Student>();

    protected override void OnConfiguring(
        DbContextOptionsBuilder optionsBuilder)
        => optionsBuilder.UseNpgsql(
            Environment.GetEnvironmentVariable("MDK0104_DB")
            ?? throw new InvalidOperationException("нет MDK0104_DB"));
}
```

<!-- notes: 5 минут. Показать, что контекст не живёт всё приложение: создали, выполнили операцию, освободили. Переменную MDK0104_DB выдаёт преподаватель. В ASP.NET Core контекст регистрируют через AddDbContext. Вопрос: почему строку подключения не хранят в коде? -->

## ChangeTracker пишет только изменённые столбцы

- При загрузке контекст запоминает состояние сущности
- `SaveChanges` генерирует `UPDATE` только для изменённых столбцов
- Поэтому метод `Update` в примере не нужен
- Для чтения без правок применяют `AsNoTracking()`

<!-- notes: 4 минуты. Связать со схемой: нижняя ветка. Вопрос: что попадёт в UPDATE, если изменить только Age? Для чтения отчётов и списков — AsNoTracking, иначе контекст копит лишние сущности. -->

## Add и Remove копят изменения до SaveChanges

```csharp
Student student = new() { Name = "Alice", Age = 20 };
context.Students.Add(student);
await context.SaveChangesAsync();

Student? last = await context.Students
    .OrderByDescending(s => s.Id)
    .FirstOrDefaultAsync();
if (last is not null)
{
    context.Students.Remove(last);
    await context.SaveChangesAsync();
}
```

## Чтение без правок ускоряет AsNoTracking

```csharp
List<Student> students = await context.Students
    .AsNoTracking()
    .OrderBy(s => s.Id)
    .ToListAsync();

foreach (Student s in students)
{
    Console.WriteLine($"{s.Id}: {s.Name}, {s.Age}");
}
```

<!-- notes: 5 минут. Запустить на таблице с Alice и Bob, показать вывод 1: Alice, 20 и 2: Bob, 22. Объяснить: AsNoTracking отключает отслеживание, объекты только для чтения. Вопрос: можно ли потом сохранить изменения такого объекта? -->

## Обновление: достаточно изменить свойство

- Запрос без `AsNoTracking` возвращает отслеживаемый объект

```csharp

if (student is not null)
{
    student.Age = 21;
    await context.SaveChangesAsync();
}
```

## LINQ переводится в SQL и работает отложенно

- SQL уходит в базу на терминальном операторе, например `ToListAsync`

```csharp
await using var context = new SchoolContext();

List<Student> adults = await context.Students
    .AsNoTracking()
    .Where(s => s.Age >= 18)
    .OrderBy(s => s.Name)
    .ToListAsync();
```

## Миграции версионируют схему без ручного SQL

- Миграция — класс с методами `Up` (применить) и `Down` (откатить)
- `dotnet ef migrations add InitialCreate` — миграция и снимок модели
- `dotnet ef database update` применяет миграции и пишет историю
- История миграций — в служебной таблице базы
- Файлы папки `Migrations` добавляют в систему контроля версий

## EF Core экономит код, но требует контроля запросов

- Ускоряет разработку: меньше ручного кода
- Типизированные LINQ-запросы: часть ошибок видна при компиляции
- Один код подключается к разным СУБД через провайдеры
- Сложные запросы могут работать медленнее ручного SQL
- Труднее контролировать SQL: помогают логи и `ToQueryString`
- N+1: отдельный запрос за связанными данными на каждую строку

## EF Core защищает параметрами, но не отменяет проверок

- Значения из LINQ, как правило, уходят параметрами
- `FromSqlRaw` со склейкой ввода — инъекция: нужны параметры
- Роль приложения — с минимальными правами
- Строка подключения — из переменной окружения
- `EnableSensitiveDataLogging()` — только при отладке
- ORM не заменяет валидацию входных данных и ограничения базы

## Миграции и три операции CRUD — в одном файле

```csharp
await using var context = new SchoolContext();
await context.Database.MigrateAsync();

context.Students.Add(new Student { Name = "Alice", Age = 20 });
await context.SaveChangesAsync();

List<Student> students = await context.Students
    .AsNoTracking().OrderBy(s => s.Id).ToListAsync();

context.Students.Remove(students[0]);
await context.SaveChangesAsync();
```
